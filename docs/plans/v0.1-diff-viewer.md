# Plan: v0.1, the read-only diff viewer

- **Title:** v0.1, the read-only diff viewer
- **Date:** 2026-09-26
- **Description:** Ship a native macOS app that opens a git repository, lists
  commits on the current branch, and renders a selected commit's diff with keyboard
  navigation. No staging, no committing, no AI.
- **Problem it solves:** Reviewing a diff or a recent commit currently means leaving
  the editor and opening a full git client, which is slow enough that the review
  gets skipped. v0.1 makes reading a diff instant and keyboard-driven.

## Not in this release

Staging, committing, AI message generation, branch switching, remotes, syntax
highlighting, and search. Each is deliberately deferred. v0.1 is judged on one
thing: whether reading a diff in Adit is faster than the alternative.

## Speed budgets

Hard limits, not goals. A step that misses one is not done.

- **Launch to commit list:** under 300 ms from cold start, on any repository. The
  paginated walk means history size does not matter.
- **Select a commit to diff painted:** under 50 ms for a typical commit (under
  1,000 changed lines).
- **Large diffs:** first screen painted in under 100 ms for 10,000+ lines, such as
  a lockfile. The rest can render lazily.
- **Navigation:** `j`/`k`, file jumps, and hunk jumps respond within one frame
  (16 ms at 60 Hz).
- **Main thread:** never waits on libgit2. Git work runs on the actor, and views
  only receive finished value types.

## Steps

1. **Add SwiftGit2** as a package dependency and confine a repository handle to an
   actor in `Git/`. Prove it by reading `HEAD` and printing the current branch name.
2. **Repo picker.** An open panel, plus a security-scoped bookmark so the last
   repository reopens on launch. Store bookmarks in `UserDefaults`, resolve on
   startup, and handle the stale-bookmark case rather than crashing.
3. **Commit list.** Walk the current branch, newest first, showing short SHA,
   summary, author, and relative date. Paginate the walk; do not load the whole
   history to display twenty rows.
4. **Diff model.** Convert libgit2's diff output into `FileChange` and `Hunk` value
   types at the git boundary. Nothing libgit2-shaped reaches the views.
5. **Unified diff view.** Render one commit's diff. Correct line numbers on both
   sides, added and removed styling, and per-file collapse.
6. **Split diff view** and a toggle between the two modes, persisted.
7. **Keyboard navigation.** `j` and `k` between commits, `⌘↓` and `⌘↑` between
   files, `n` and `p` between hunks. Full-keyboard operation is the point, not a
   nice-to-have.
8. **Measure.** Check every budget above against real repositories, including a
   large diff such as a lockfile change or a vendored dependency bump. Each step
   from 3 onward is also timed as it lands, so a regression shows up at the
   step that caused it. If rendering misses a budget, switch the renderer per
   `ARCHITECTURE.md` before adding anything else.

## Definition of done

Jordan uses Adit instead of anything else to review his own commits for a week, and
does not reach for a terminal or another client to read a diff.

## Risks

- **Large diffs.** The likeliest failure. Step 8 exists to catch it while the code
  is still small enough to change the renderer cheaply.
- **Sandbox and bookmarks.** Easy to get subtly wrong so that access silently fails
  on second launch. Test relaunch explicitly in step 2, not at the end.
- **libgit2 concurrency.** Handles are not thread-safe. The actor confinement in
  step 1 is load-bearing; do not reach around it later for convenience.
